# P131 Single-Writer Checkpoint and Export Hygiene

P131 defines and implements the burn harness artifact ownership policy for
multi-process runs. P130 proved synchronized updates for the minimal sharded
trainer; P131 makes the output layer deterministic and non-racy without
changing training math, example sharding, WKV/Pallas behavior, or target loss
semantics.

## Artifact Ownership Policy

Canonical artifacts are written only by JAX process 0. Per-process diagnostic
artifacts are written with process-index-specific names. The canonical process
index is always `0`, and reports advertise the policy as
`process_0_canonical_with_per_process_diagnostics`.

| Artifact | Owner | Path policy |
| --- | --- | --- |
| `checkpoint.json` | Process 0 only | Canonical checkpoint. Nonzero processes skip it. |
| `burn_report.json` | Process 0 only | Canonical burn report. |
| `burn_report_process_<index>.json` | Every process | Per-process burn diagnostics. |
| `readiness_report.json` | Process 0 only when generated by the burn harness | Nonzero processes keep the expected path in reports but do not write it. Caller-provided readiness reports are read-only inputs. |
| `loss_trace.json` | Process 0 only | Canonical local/global loss trace for the canonical writer. |
| `launch_commands.md` | Process 0 only | Canonical launch instructions. |
| `sync_report_process_<index>.json` | Every process | Per-process sync diagnostics. |
| `sync_global_report.json` | Process 0 only | Process-0 global collective view. |
| `example_shard_process_<index>.json` | Every process | Per-process example-shard diagnostics. |
| `example_sharding_global_report.json` | Process 0 only | Global example coverage and overlap report. |

Dry-run preflight/checkpoint/eval artifacts remain single-process harness
outputs and do not imply distributed production readiness.

## Report Fields

Real burn reports now include explicit artifact ownership metadata:

- `artifact_hygiene_ready`
- `artifact_write_policy`
- `canonical_process_index`
- `is_canonical_process`
- `report_role`
- `report_writer_process_index`
- `canonical_burn_report_path`
- `per_process_burn_report_path`
- `per_process_report_paths`
- `per_process_reports_written`
- `per_process_diagnostics_preserved`

Checkpoint reports now use single-writer semantics:

- `checkpoint_write_strategy: process_0_only`
- `canonical_checkpoint_writer_process_index: 0`
- `canonical_checkpoint_written`
- `canonical_checkpoint_written_by_this_process`
- `canonical_checkpoint_path`
- `canonical_checkpoint_fingerprint`
- `checkpoint_fingerprint_comparison_scope: canonical_process_0_only`
- `checkpoint_fingerprint_match: true`
- `checkpoint_fingerprint_match_meaning`
- `single_writer_checkpoint_verified: true`

`checkpoint_fingerprint_match=true` means the canonical checkpoint writer was
verified under the process-0-only policy. It is not an N-way independent
checkpoint byte comparison.

## Claims

P131 may preserve `distributed_training_ready=true` when the P130 predicates
remain satisfied. It adds `artifact_hygiene_ready=true` and
`single_writer_checkpoint_verified=true` for the burn harness artifact layer.

P131 still does not claim model quality, production training readiness,
large-scale performance, Qwen/tokenizer remapping support, Pallas default
readiness, WKV/runtime math changes, or automatic large burn launch.

`production_training_ready` remains `false`.
